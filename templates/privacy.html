Privacy Policy

Effective date: 20 September 2026

MarkMyPaper is software you install and run on your own computer. This policy describes what the application stores, what it sends, and what it never sees. The short version is at the end of each section.

1. Scope

This policy assumes the typical setup described in the repository README: the application runs on your machine and serves its pages over localhost or your own network. Anything you do with a modified, recompiled, or redeployed version is outside this policy, and any hosted deployment you create is your own processing environment.

2. What the application stores

The application keeps two kinds of records in a local SQLite file (instance/users.db):

  • Registration records: the name, email, password hash, and creation time of each registered account, created only when a person submits the registration form.
  • Grading records: for every completed run, the uploaded file name, page count, extraction method per page, the extracted text, the list of model answers and weights supplied, per-answer similarity and score, and the total score and possible maximum.

The extracted text is kept together with the run so the history page and future updates can show what was graded. It is stored on the same machine that performed the OCR.

Short version: account details and grading transcripts, in one local database file.

3. Files you upload

A submitted file is read into memory on the server (your machine), transcribed if it contains image pages, and discarded from schedule after the run. The original file bytes are not written to the database. The extracted text derived from the file is kept, as described in the previous section.

Short version: the sheet itself is processed in memory and not saved; its extracted text is saved.

4. Network communication

On first startup the application downloads the TrOCR model weights from Hugging Face. This is a request from your machine to Hugging Face's servers, and it sends only the ordinary HTTP request for the model files. It does not send your sheets, your text, or your account data. If your network blocks or logs outbound requests, that is your own environment.

The application does not contain analytics, advertising, tracking pixels, or third-party script embeds in its pages. The only scripts are the application's own, served from the same machine. Fonts and icons are loaded from Google Fonts and your local stylesheet; if you prefer no network requests at all, self-host the fonts.

Short version: one model download on first run to Hugging Face, and nothing else leaves your machine.

5. Passwords and tokens

Passwords are stored as salted scrypt hashes computed with werkzeug's current default scheme, not as plain text. After login and registration the server issues a JSON Web Token, which the browser keeps in its local storage and sends back in the Authorization header for protected routes. The token expires after one day. Clearing your browser's local storage logs you out.

Short version: hashed passwords in the database, a 24-hour token in your browser's local storage.

6. Your control

Because all data lives in instance/users.db on your computer, control is literal: you can inspect the file, back it up, or delete it. Deleting the file erases account records and grading transcripts together. The application has no remote storage from which it could recover them. Verifying and adjusting what the application stores is done by editing the application code you run.

Short version: it is your file, in your hands. Delete it and the data is gone.

7. Children

The application is intended for teachers and graders. If student names or marks pass through the system, they are processed under the account and responsibility of the institution that runs it, as described in the Terms of Service. The application is not directed at children as users, and accounts are not intended for minors.

8. Changes to this policy

This policy tracks the behavior of this version of the software. Future versions that change what is stored, sent, or retained will have this document updated in the same repository, with a new effective date at the top. The version-controlled history is the record of every change.

9. Contact

Questions about this policy should be raised in the repository issue tracker at github.com/DysCreate/MarkMyPaper/issues, which is the only point of contact for this project.
